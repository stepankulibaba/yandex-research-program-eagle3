# Условия и критерии экспериментов

## Основа кода

Обучение использует проверенное подмножество определений NeMo `3914f200a4c782d44b58ee7a01b4685e4158e19c`, извлечённых через AST без изменения их вычислений. Дерево и проверка принятия основаны на EAGLE `cb7e0841fe0c206c6ed74a197ad5e2a1f13f5a2b`. Полный рецепт NeMo с распределённым обучением, BF16 и FlashAttention не запускался.

Готовый драфт `AngelSlim/Qwen3-1.7B_eagle3`, версия `94441b48acc5804677ae12259617c83323b543a9`; цель `Qwen/Qwen3-1.7B`, версия `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`. Входную матрицу не переинициализировали. Она дообучалась вместе с остальными параметрами драфта.

## Дообучение

Пул UltraChat: 600 строк, шесть блоков по 100; 400 из `train_sft`, 200 из `test_sft`. Это ограниченный пул, его представительность для всего датасета не установлена. Версия `main` проверена до и после выгрузки; закрепить версию в Dataset Viewer нельзя.

Использовали первый пользовательский ход, длина запроса после шаблона 16–256 токенов. Убрали совпадения идентификаторов и нормализованных запросов; семантический поиск утечек не выполнялся. Дополнительные 72 примера выбирали по близости длины к исходным 24, без просмотра ответов или метрик. Новые 32 проверочных запроса исключены из обучения и прежней проверки. После этого опыта они уже просмотрены и не считаются нетронутой выборкой для следующих решений.

Ответы генерировала целевая модель: жадный выбор токена, рассуждения выключены, естественный конец ответа, предел 128 новых токенов. Полным проходом по сохранённым ответам получали признаки и вероятности цели. Подготовку ответов выбрали для этого протокола; NeMo допускает получение обучающих сигналов прямым проходом по готовым ответам датасета.

Четыре независимых старта одинакового готового драфта: 24/96 примеров × скорости `1e−4`/`1e−5`. AdamW: betas `(0,9; 0,95)`, eps `1e−8`, без затухания весов, ограничение нормы градиента 1, масштаб потерь 128. Скорость постоянная. FP16 для вычислений, FP32 для основных копий весов и состояния оптимизатора. Пакет 1, TTT 7.

На условие ровно 79 712 входных токенов: длина запроса вместе с ответом, с учётом всех повторных проходов. Для 24 примеров 384 обновления; для 96 примеров 381, с детерминированной обрезкой до точного бюджета. Маски, вероятности, функция потерь и градиенты после обрезки проверены до обучения. Равенство токенов не гарантирует равенство операций, времени или позиций функции потерь.

## Метрика принятия

Драфт строит дерево при движении по известному продолжению целевой модели. Число узлов 64, глубина 2, top-k 10. В число выданных токенов входит корневой или дополнительный токен цели; превышение длины сохранённого ответа исключено.

$$\tau_{fixed}=\frac{\text{число полезных токенов}}{\text{число циклов проверки}}.$$

У всех вариантов продолжение одинаковое. Это оценка принятия по сохранённым ответам, без измерения времени генерации. Абсолютные значения не сопоставляются с цепочечной метрикой или деревом из статьи.

Парное изменение к исходному драфту: геометрическое среднее отношений по одним и тем же запросам. Общая τ по сумме токенов и циклов приводится отдельно.

До расчётов заявлены три критерия:

- **H27:** меньшая скорость обучения лучше в среднем по двум корпусам.
- **H28:** больший корпус лучше в среднем по двум скоростям.
- **H29:** заранее выбранный вариант 96 / `1e−5` лучше исходного драфта.

Для каждого запроса H27 = √[(τ24_low/τ24_high)·(τ96_low/τ96_high)], H28 = √[(τ96_high/τ24_high)·(τ96_low/τ24_low)], H29 = τ96_low/τ_initial.

Критерий: среднее отношение > 1, нижняя граница интервала > 1, положительный эффект минимум на 24 из 32 запросов. Парная повторная выборка запросов: 20 000 повторов, seed `20261008`. Поправка Бонферрони для трёх критериев даёт двусторонние интервалы 98,3333%. Остальные 95%-интервалы описательные. Интервалы по запросам не описывают разброс между обучениями или составами корпуса.

## Память и Triton

Пакет 2, TTT 7; вычисления FP16, основные веса и AdamW FP32, готовые признаки цели. Четыре синтетических документа: два калибровочных и два проверочных. Калибровочные длины 166/256/512, проверочные 384/640/896/1024. Время измеряли на 166/768 шестью парными повторами в чередующихся порядках. Сетка вместимости 512/640/768/896/1024, по три обновления в обоих порядках при лимите распределителя CUDA 6144 МиБ.

Варианты: `dense` с копиями сдвигов; `split` с общим буфером и обработкой отдельных элементов пакета; `stride` с общим буфером и одним вызовом доработанного ядра для всего пакета. Перед зависимыми замерами проверяли градиенты и состояния после обновления. Значения функции потерь могли различаться в исходном допуске; допуск ради успеха не меняли.

Порог ускорения полного шага: отношение времени ≥ 1,02 и нижняя граница технического 95%-интервала > 1. Эти повторы характеризуют данную сессию и формы входа.
