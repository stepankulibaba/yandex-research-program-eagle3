# Обучение драфта EAGLE-3 с нуля: слои статьи против наших

Два драфта для LLaMA-3.1-8B-Instruct, обучаемые с нуля **кодом авторов** (SafeAILab/EAGLE, закреплённый коммит; DeepSpeed fp16, 7 шагов TTT, 8 диалогов на шаг, lr 5e-5) на одних и тех же данных, в одном порядке, одинаковое число шагов — до 0,4 эпохи (68 325 шагов, 546 600 диалогов). Различаются только входом:

| вариант | слои цели (вход слоя i) | перед `fc` |
|---|---|---|
| `baseline` — EAGLE-3 как в статье | 2, 16, 29 | — |
| `ours` — наш метод | 16, 22, 29 (N/2, 0,7N, N−3) | RMSNorm на каждый слой с обучаемым масштабом (EAGLE-3.1 `fc_norm`) |

Сначала `ours` учили рецептом NeMo AutoModel (`train_nemo_full.py`). Он не годится для этой задачи: в опубликованном виде (bf16-веса и AdamW) теряет мелкие обновления, а с fp32-мастер-весами расходится при любом lr от 2e-4 до 2e-5 около шагов 600–930 (рост логитов внимания q·k). Разбор, графики и логи — [отчёт](../reports/eagle3_nemo_incident.pdf) и `../results/llama31-8b/nemo_incidents/`. Поэтому с 13.10 00:12 `ours` продолжает прогон на коде авторов, начатый 12.10 и остановленный на шаге 998.

Файлы: `train.py` (оба варианта, код авторов + `patch_eagle.py`), `train_nemo_full.py` (NeMo-вариант, не используется), `session.py` (запуск обоих в сессии), мониторинг — `monitor.py`, `bot.py`, `dashboard.py`, `clearml_sync.py`, `relay.py`.

## Протокол

| | значение | откуда |
|---|---|---|
| данные | PerfectBlend-Regenerated-Llama-3.1-8B-Instruct, 1,42 млн диалогов, ответы уже сгенерированы целевой моделью; 2000 диалогов отложены на валидацию | готовый набор, на нём учат SpecForge и рецепт NeMo |
| токенизация и маска loss | функция предобработки авторов как есть; примеры длиннее 2048 токенов выбрасываются | код авторов |
| словарь драфта | 32 тыс. самых частых токенов ответов в наших данных | как `scandata` авторов |
| TTT | 7 шагов, веса потерь 0,8^i | код авторов |
| оптимизатор | AdamW (0,9; 0,95), lr 5e-5, weight decay 0, клиппинг 0,5 | статья и код |
| точность | fp16 с динамическим loss scaling (DeepSpeed, ZeRO-2) | код авторов |
| батч | 8 диалогов на шаг (у авторов 4 GPU × 1 × 2; у нас 1 × 8) | код авторов |
| расписание lr | разогрев min(12 000, 10 % плана) шагов, линейный спад до 0 к последнему шагу плана | у авторов спад зашит до шага 800 000 — поменяли на наш план |
| эпохи | столько шагов, сколько помещается до срока (`plan.py`): меньше одной эпохи, все примеры разные | решение тимлида: режем эпохи, не данные |
| gradient checkpointing | выключен (то же самое численно, быстрее; память есть) | |

Найдено при подготовке и учтено:
- у авторов расписание lr зашито до шага 800 000, а батч 8 получается только на 4 GPU;
- словарь драфта у авторов молча берётся из `cache.pt` в текущей папке — у нас он строится по нашим данным;
- маска loss авторов в многоходовых диалогах не учитывает 2 последних токена каждого ответа, кроме последнего (~0,2 % токенов) — оставили как есть, одинаково для обоих вариантов;
- код генерации авторов грузит веса драфта с `strict=False`, а SGLang молча пропускает незнакомые веса: без проверки `fc_norm` нашего варианта тихо потерялся бы. Теперь и там и там отсутствие весов — ошибка;
- SGLang и NeMo считают слои как «выход слоя i»: наши 16, 22, 29 — это у них 15, 21, 28 (`export.py`).

## Как запускать на H200

Код лежит рядом с папками репродукции: `~/data/big_training`, `~/data/inference_speed` (клон EAGLE, модели, `venv_eagle`), `~/data/nemo_speed` (`venv_orig` с DeepSpeed). В репозитории это `big-training/code/`, `reproduction/code/inference_speed/` и `reproduction/code/nemo_speed/`: папка `code/` копируется на сервер как `~/data/big_training` (`cp -r big-training/code ~/data/big_training`), пути в `settings.py` считаются от её родителя.

**0. Секреты** (один раз). Файл `~/.eagle_secrets`, `chmod 600`, строки `KEY=value`:
```
TELEGRAM_BOT_TOKEN=...      # бот от @BotFather
TELEGRAM_CHAT_ID=...        # свой chat id (владелец)
TELEGRAM_ALLOWED_IDS=...    # кому ещё можно смотреть: id людей или командной группы через запятую
CLEARML_API_HOST=...        # из ClearML: Settings → Workspace → Create new credentials
CLEARML_WEB_HOST=...
CLEARML_FILES_HOST=...
CLEARML_API_ACCESS_KEY=...
CLEARML_API_SECRET_KEY=...
```
Без них всё работает, сообщения пишутся только в `runs/monitor.log`.

**1. Подготовка** (CPU, ~15 мин): `bash setup.sh` — клиент ClearML, патченные копии кода авторов, данные (`data/`, `data_smoke/`).

**2. Смоук** (первая сессия, ~30–40 мин GPU): `nohup setsid bash smoke.sh > smoke.out 2>&1 &`. Проверяет всё по разу на 4000 диалогах:
- крошечная модель: слои, `fc_norm`, загрузка в код генерации;
- оба варианта по 150 шагов, один прерывается и продолжает с чекпоинта;
- официальный драфт на валидации;
- настоящий τ кодом авторов.

В конце `smoke.out` — вердикт и измеренная скорость.

**3. План** (один раз): `../nemo_speed/venv_orig/bin/python plan.py "2026-10-15 10:00"` — срок окончания обучения. Число шагов считается по скорости из смоука; 3 ч оставлены на итоговую оценку.

**4. Каждая сессия:** `nohup setsid bash session.sh > session.out 2>&1 &`. Сама продолжит с чекпоинтов и сохранится за 12 минут до конца сессии SLURM.

**Посмотреть, как идёт:**
- Telegram-бот (`bot.py`, его поднимает сессия): кнопки 📊 статус, 🎯 качество (τ-оценка, разница вариантов), 🔮 прогноз, 📉 кривые, 🖥 GPU, 🚨 тревоги, 🔔 подписка на тревоги и часовую сводку. Только чтение: управлять обучением через бота нельзя. Отвечает только тем, кто в `TELEGRAM_CHAT_ID` / `TELEGRAM_ALLOWED_IDS`; остальным пишет их id, чтобы владелец мог добавить;
- `tail runs/monitor.log` — сводка и тревоги;
- `cat runs/*/status.json`;
- ClearML — кривые обоих вариантов.

**Управление:**
- `touch runs/<variant>/CKPT` — сохраниться сейчас;
- `touch runs/<variant>/STOP` — сохраниться и остановиться.

## Что считается

- **Валидация** — каждые 2000 шагов на 400 отложенных диалогах. Метрики: точность по 7 позициям TTT и оценка τ = 1 + Σ_k Π_{j≤k} acc_j (цепочка, грубее настоящего τ по дереву, зато дёшево и одинаково для обоих).
- **Прогноз** (`monitor.py`, раз в час): кривая τ(диалоги) = a − b·диалоги^(−c) по точкам валидации. Даёт значение к концу плана, после полной эпохи и сколько диалогов нужно до уровня официального драфта (`runs/reference.json`).
- **Сравнение** вариантов — на равных шагах: веса обоих сохраняются каждые 10 000 шагов (`runs/<variant>/milestones/`). Итоговый τ — `eval_tau.py` (код авторов, дерево 60/8/10) и SGLang.
