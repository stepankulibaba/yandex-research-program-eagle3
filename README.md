# EAGLE-3: воспроизведение и исследование

Yandex & Sirius Research Program 2026.

**EAGLE-3** ускоряет генерацию больших языковых моделей. Маленькая модель-драфт быстро угадывает несколько следующих токенов, а большая модель (её называют target) проверяет все догадки за один проход. Чем больше токенов принято за один проход, тем быстрее генерация. Эту величину мы обозначаем **τ**: τ = 3 значит, что за один проход большой модели получается в среднем 3 токена вместо одного.

Чтобы угадывать лучше, драфт подглядывает во внутренние состояния большой модели — в три её слоя. Какие это слои, в EAGLE-3 зашито в код, и они одинаковы для любой модели.

## Что мы выяснили

- **Статья воспроизводится по τ.** На LLaMA-3.1-8B-Instruct с официальным драфтом и деревом из статьи τ совпал в пределах 1 %: 6,25 против 6,23. Ускорение зависит от машины: 3,38× на H200, 4,02× на A100, в статье 4,44×. Ускорение — это отношение к обычной генерации на той же машине, поэтому чем она быстрее, тем оно меньше. → [reproduction](reproduction/)
- **В оптимизированном движке SGLang** EAGLE-3 абсолютно быстрее кода авторов почти вдвое, но **дерево NeMo по умолчанию теряет треть ускорения** (1,94× против 3,06×).
- **Обучение:** NeMo быстрее кода авторов всего в 1,06–1,24×. Повторить обучение авторов (40 эпох) — это ~660–800 GPU-часов H200; в 100 ч помещаются 2–3 эпохи по всем данным.
- **Слои, которые берёт EAGLE-3, выбраны не лучшим образом.** Самый нижний из трёх почти не используется; полезная зона — около 70 % глубины сети и самый верх. На Qwen3-1.7B замена слоя даёт +8 % τ, на DeepSeek-8B с сильным официальным драфтом — ничья. → [layer-selection](layer-selection/)
- **Выбор слоёв для каждого токена (роутер, MoE) не нужен:** на обеих моделях он не лучше удачной фиксированной тройки.
- **Вне английского ускорение почти исчезает.** На русском и японском τ около 1,6–2: у драфта урезанный словарь. → [extra-checks](extra-checks/)

## Как устроены папки

В каждом направлении одинаково:
- `README.md` — вопрос, что сделали, что получилось, что это значит;
- `reports/` — отчёты в PDF;
- `figures/` — графики, их строят скрипты `code/make_*.py`;
- `results/` — результаты: таблицы, json, логи;
- `code/` — код и инструкция, как его запустить.

Модели, данные и окружения в git не хранятся. Как их получить, написано в README каждого направления.

Правила для тех, кто дописывает репозиторий, в том числе для ИИ-агентов, — в [AGENTS.md](AGENTS.md).
