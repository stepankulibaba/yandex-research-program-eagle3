# SpecVocab на языках: динамический словарь драфта EAGLE-3 на Qwen3-1.7B

Реализация идеи **SpecVocab** — Williams et al., *Speculative Decoding with a Speculative Vocabulary*, 2026, [arXiv:2602.13836](https://arxiv.org/abs/2602.13836) — и проверка того, чего в статье нет: как она ведёт себя на неанглийских языках.

## Зачем

У драфта EAGLE-3 выходной слой урезан до 32 тыс. самых частых токенов английских данных. Драфт не может предложить токен вне словаря, поэтому цепочка обрывается на первом таком токене. Наш прошлый замер (папка `extra-checks`) — для Qwen3-1.7B с драфтом AngelSlim:

| язык | доля токенов ответа вне 32K | τ | ускорение |
|---|---|---|---|
| английский | 3 % | 3,65 | 2,25× |
| русский | 49 % | 1,71 | 1,13× |
| украинский | 61 % | 1,44 | 0,88× |

SpecVocab вместо фиксированного словаря выбирает кандидатов на каждом шаге:

1. дешёвый низкоранговый ранжировщик оценивает **весь** словарь: `s = W_vocab · (W_down · h)`, где `d' = d/8`;
2. из рейтинга берутся `k` лучших токенов (в статье `k = 2048`);
3. точные логиты считаются только по ним полной головой: `z = U[K] · h`.

Обучение без top-k: `L = L_TTT(p, softmax(U h)) + 0,1 · L_TTT(p, softmax(s))`. В статье: +4,8 % к τ и до +8 % пропускной способности против EAGLE-3 на английском Spec-Bench. Языки авторы не проверяли и прямо называют это ограничением.

**Вопрос этого опыта:** закрывает ли SpecVocab языковой провал EAGLE-3 и какой ценой (k, полнота кандидатов, стоимость головы).

## Варианты

Все стартуют с одного официального драфта `AngelSlim/Qwen3-1.7B_eagle3` и учатся бок о бок на одних текстах в одном порядке; прямой проход большой модели общий. Учится весь драфт (fc, слой декодера, нормы, голова), большая модель заморожена.

| вариант | голова | что учит |
|---|---|---|
| `static32k` | официальная, 32K токенов (EAGLE-3 как есть) | распределение цели, урезанное до 32K |
| `full` | весь словарь, 151 936 токенов | полное распределение (верхняя граница по τ, медленная голова) |
| `specvocab` | весь словарь + ранжировщик `d' = 256` | полное распределение; ранжировщик с весом 0,1 |

Плюс в оценке — `official`: тот же драфт без дообучения.

**Инициализация (наше решение; в статье обучение с нуля).** У официального драфта есть строки головы только для 32K токенов. Остальные ~120K строк берутся из выходной матрицы самой Qwen3-1.7B, переведённой в пространство головы драфта линейным отображением, подобранным по 32K общим токенам (наименьшие квадраты). Ранжировщик SpecVocab стартует как лучшее приближение полной головы ранга 256 (усечённый SVD).

**Обучение — как в наших прошлых запусках** (`routed_release`): ответы самой модели (жадно, до 512 токенов) на 6000 запросов UltraChat и 2000 задач GSM8K, 3 эпохи, развёртка драфта на 6 шагов с весами 0,8^(s−1), AdamW (0,9; 0,95), lr 5·10⁻⁵ (ранжировщик 10⁻⁴), warmup 50, cosine, clip 0,5, один текст на шаг.

`DATA=ml` добавляет многоязычные запросы (OpenAssistant oasst2: ru, uk, de, zh, ja, до 800 на язык) — чтобы отделить эффект головы от эффекта данных.

## Запуск

```bash
git clone -b specvocab-languages https://github.com/stepankulibaba/yandex-research-program-eagle3
cd yandex-research-program-eagle3/specvocab
SMOKE=1 bash run.sh      # 10–15 минут: каждый шаг на 24 текстах — убедиться, что всё работает
bash run.sh              # полный прогон на английских данных
DATA=ml bash run.sh      # то же + многоязычные данные (можно после первого)
```

Нужны Python 3.10+, драйвер CUDA 12, одна GPU от 40 ГБ (A100/H100/H200) и интернет (Hugging Face). Каждый шаг пропускается, если уже сделан: после сбоя запустите ту же команду. Обучение сохраняет чекпоинт каждые 2000 шагов и продолжается с него.

Шаги `run.sh`:

1. `.venv` из `requirements.txt` и проверки на CPU (`tests/test_cpu.py`);
2. вопросы MT-bench / GSM8K / HumanEval из репозитория EAGLE (коммит `cb7e0841`);
3. модели `Qwen/Qwen3-1.7B` и `AngelSlim/Qwen3-1.7B_eagle3` (~4 ГБ);
4. тексты: 240 английских вопросов, 660 языковых (60 m-ArenaHard + 60 MGSM на en, ru, uk, de, zh, ja; у украинского нет MGSM), 8000 обучающих — ~1–1,5 ч на H200;
5. `sanity.py`: наш код с официальным драфтом должен дать высокую τ и быть заметно лучше, чем с неверным RoPE; иначе стоп;
6. обучение (`train.py`), лог — `logs/train_<run>.log`: через несколько минут там видно `s/step`;
7. итоговая оценка (`evaluate.py`), стоимость голов (`head_speed.py`), таблицы и графики (`analyze.py`);
8. архив `results_<run>.tgz` — его и прислать.

## Что меряется

На ответах самой модели при температуре 0 драфт принимается, когда его догадка совпадает с argmax цели, поэтому один проход цели по тексту даёт исход каждой догадки (`metrics.py`, `evaluation.py`):

- **τ (цепочка)** — 1 + средняя длина принятого префикса цепочки из 6 шагов, начатой с каждой позиции ответа; **τ по циклам** — то же в симуляции настоящего декодирования;
- для SpecVocab — τ при `k` = 256, 512, 1024, 2048, 4096 и без отбора (вся голова), и **полнота кандидатов**: доля шагов, где нужный цели токен попал в `k` кандидатов;
- **доля токенов ответа вне 32K** по языкам;
- **стоимость головы**: умножения на токен и время на GPU для батча 1 и 60 (дерево EAGLE-3), обычный PyTorch без fused-ядра статьи.

Оговорки: τ — по цепочке (одна ветка), не по дереву EAGLE; реальная скорость генерации не меряется — для неё нужен SpecVocab в движке (SGLang) и ядро из статьи. Цепочечная τ честно сравнивает варианты между собой.
