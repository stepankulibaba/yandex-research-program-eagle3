# Задача 5: бюджет GPU-часов на обучение драфта с нуля (H200)

Считает `code/inference_speed/budget.py` по двум замерам:
- **регенерация** (`regen_probe.py`): таргет переписывает ответы ассистента в обучающих диалогах, как в статье. Работает через SGLang, обычный сервер без спекуляции, 64 параллельных запроса;
- **скорость шага обучения** из задачи 4 ([training_speed.md](training_speed.md)).

## Данные

| источник | диалогов | заметка |
|---|---|---|
| ShareGPT V4.3 (`Aeala/ShareGPT_Vicuna_unfiltered`) | 68 623 | это и есть 68K из статьи |
| UltraChat-200K `train_sft` | 207 865 | |
| UltraChat-200K `train_gen` | 256 032 | только промпты; ответы генерирует таргет |
| **всего** | **~532 тыс.** | в расчёт идёт только доля, пригодная по нашей политике |

Политика регенерации наша, в статье её нет:
- переписываем все ходы ассистента, greedy, с системным промптом авторов;
- не больше 512 токенов на ход и 1900 на пример;
- диалоги, которые не влезают, отбрасываем целиком.

## Результат (центральная оценка, 10 ч запаса внутри 100 ч)

| | GPU-часов H200 |
|---|---|
| Регенерация всего корпуса (один раз) | **38,1** |
| Эпоха: код авторов как есть | 18,9 |
| Эпоха: NeMo, упаковка | 17,9 |
| Эпоха: NeMo + compile | 15,5 |
| Эпоха: NeMo + compile + FP8 | **15,3** |

| сценарий | код авторов | NeMo + compile + FP8 |
|---|---|---|
| все данные: сколько эпох влезает в 100 ч | **2** (86 ч) | **3** (94 ч) |
| 5 эпох | 68 % данных (медленный сценарий 45 %) | 79 % (53 %) |
| 10 эпох | 40 % (26 %) | 47 % (32 %) |
| 40 эпох, как в конфиге авторов | 11 % (8 %); на все данные 804 ч | 14 % (9 %); на все данные 658 ч |

«Медленный сценарий» — все затраты ×1,5. Это проверка чувствительности, а не доверительный интервал.

## Что это значит

- **Повторить обучение авторов (40 эпох по всем данным) в 100 GPU-часов нельзя:** нужно ~660–800 ч H200.
- **В 100 ч помещаются 2–3 эпохи по всем перегенерированным данным.** Главная ставка статьи EAGLE-3 — рост качества драфта с объёмом данных, поэтому урезать лучше эпохи, а не данные.
- **Кэшировать скрытые состояния таргета вместо его прогона каждую эпоху нереально:** 11,6 ТБ.
- **A100 (оценка, не замер):** примерно в 2,5 раза медленнее H200 и без FP8. Одна регенерация заняла бы ~95 ч, то есть почти весь бюджет. Регенерацию и обучение выгоднее делать на H200.

## Оговорки

- **Регенерация, скорее всего, посчитана с запасом.** Время мерили на группах по ≤64 диалога вместе с «хвостом»: в конце группы работают 2–11 запросов, а не 64. Кэш KV при этом был занят всего на 3 %. Непрерывный поток с батчем 256+ может ускорить регенерацию в 2–4 раза. Это не замерено.
- Скорость обучения мерили на другом корпусе (PerfectBlend), доли длин диалогов — по выборке, а не по всему корпусу.
- Не учтены оптимизации шага, которые мы не проверяли: больший микро-батч (заняты 28–37 из 141 ГБ), FlashAttention/SDPA, fused cross-entropy.
