# История исправлений

Что ломалось при подготовке и прогонах и как это исправлено. Числа в отчётах получены уже после всех исправлений.

## Ошибки в коде авторов (обходим, не меняя их замер)

| Что | Последствие | Что делаем |
|---|---|---|
| Скрипт оценки по умолчанию берёт `--depth 5` — дерево EAGLE-2 (глубина 6), а не глубину 8 из статьи EAGLE-3 | τ на 10 % ниже статьи, легко решить, что статья не воспроизводится | Передаём явно `--total-token 60 --depth 7 --top-k 10`; в SGLang дерево статьи — 8/10/60 |
| `--max-new-token 1024` объявлен, но в генерацию не передаётся | Фактический лимит ответа — 512 токенов | Сохраняем как у авторов и пишем об этом |
| `traineagle3/cnets.py` читает `self.train_config.gradient_checkpointing` и `.max_len`, а `main.py` передаёт словарь | Опубликованный тренер падает при создании модели | Исправляем в копии (`nemo_speed/patch_original.py`) |
| `speed.py` считает только ускорение | τ нет | τ берём по определению статьи из счётчиков генератора |

## Надёжность ночного прогона

- **Готовое не теряется.** У каждого результата есть отметка `<файл>.done.json` с настройками, при которых он получен. При перезапуске подходящий результат берётся без пересчёта (`REUSED`). Результаты 3a прошлой версии кода принимаются, если совпадают дерево, температура, модели, железо и пакеты (`ADOPTED`). `REUSE_IGNORE_ENV=1` разрешает принять результат, если изменился только список пакетов окружения.
- **Одна ошибка не обрывает ночь.** Упавшая стадия получает `FAILED`, остальные идут дальше. Останавливают прогон только общий дедлайн и сигнал. В конце печатается список упавших стадий.
- **Скачивание.** Модели берутся по закреплённым ревизиям, после скачивания проверяются размеры, индексы и заголовки safetensors. Уже проверенная модель проверяется локально, без обращения к Hub.
- **Серверы SGLang.** Перед стартом проверяется, что порт свободен; это нужно, потому что предыдущий сервер освобождает его не сразу. Сервер, не поднявшийся вовремя, — ошибка этой стадии, а не всей ночи. Свои процессы убиваются группой.
- **Таймаут бенчмарка** — 90 минут: обычная генерация авторов на MT-bench дольше 30.

## Честность сравнений

- **3b, счётчики SGLang.** В SGLang 0.5.9 поле называется `meta_info.spec_accept_token_num`; при нуле раундов счётчиков нет вовсе. τ = (сгенерировано − 1) / число проверок: первый токен SGLang выдаёт на prefill. Тот же счёт, что у авторов.
- **3b, T = 1.** Сервер с `--random-seed 0`: проверка дерева при T = 1 берёт глобальный генератор сервера. Перед замером проверяется, что ядро сэмплирования дерева есть; без него SGLang молча проверял бы жадно. Три seed.
- **3b, протокол.** Без кэша префиксов, не больше 512 новых токенов за ход, стоп-токены как у авторов (`eos` и `<|eot_id|>`), прогрев — первый вопрос всеми ходами трижды.
- **4, два режима обучения.** «Уравненный» (BF16, строки по 2048, постоянный lr, без checkpointing) сравнивает реализации на одинаковой работе. «Как есть» (`original_asis`: fp16, checkpointing, без паддинга, расписание авторов) — честная база для NeMo с упаковкой и для бюджета. Данные и словарь на 32K у обоих тренеров общие.
- **4, накопление градиента.** В копии тренера авторов убран `model.zero_grad()` на каждом микро-батче, иначе накопление не работало.
- **5, веса сплитов.** Каждый сплит взвешивается своим реальным размером: раньше `train_sft` и `train_gen` UltraChat сливались 50/50 при реальных 45/55. Не влезающий диалог отбрасывается целиком, как это делает тренер авторов.

## Сервер без CUDA toolkit

- **DeepSpeed** спрашивает `nvcc -V` при установке и при каждом импорте. Он получает заглушку, которая печатает версию CUDA из torch. Ничего не компилируется.
- **SGLang 0.5.9:**
  - инициализирует DeepGEMM при импорте и требует `CUDA_HOME` (JIT DeepGEMM выключен: `SGLANG_ENABLE_JIT_DEEPGEMM=0`);
  - на старте компилирует ядро RoPE, поэтому нужен настоящий компилятор, а не заглушка. `setup_cuda.sh` ставит настоящий CUDA 12.8 и gcc 13 из conda-forge без root, в `../cuda-home`; путь получают только процессы SGLang;
  - пакет `kernels` новой версии ломает старт сервера, удаляем его;
  - драфт должен иметь `architectures = ["LlamaForCausalLMEagle3"]`, иначе грузится как обычная Llama. Даём SGLang копию конфига с этим полем (веса — ссылки на те же файлы) и `SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1`.
- **flash-attn 2** не ставится, варианты с ним получают `UNSUPPORTED`.

## Данные для регенерации (задача 5)

- **ShareGPT** читается напрямую из файла `ShareGPT_V4.3_unfiltered_cleaned_split.json` — того, что использовали авторы. Потоковый `datasets` портил его записи. В файле 68 623 диалога — это и есть 68K из статьи.
- **UltraChat `train_gen`** содержит только промпты, без ответов. Такие диалоги принимаются: ответы всё равно генерирует таргет. Начальные реплики модели перед первым вопросом пользователя отбрасываются.
- **Скрипты с потоковым `datasets`** завершаются через `os._exit(0)`: иначе Python падает на выходе уже после записи результатов.

## Профиль

- **Метки фаз** в `torch.profiler` попадали в GPU-время, отсюда «GPU busy 177 %». Теперь они исключаются из подсчёта.
- **Трасса полного ответа** весила ~2 ГБ и не успевала записаться за час. Под профилировщиком теперь отвечаем на 128 токенов, лимит стадии — 2 ч.
- **Нижняя граница шага** (прочитать веса один раз) считается по пропускной способности памяти конкретной видеокарты. Раньше было зашито значение для H200.

## Как проверялось без GPU

- `test_regressions.py` — 17 тестов без torch и CUDA: отметки «готово», разбор результатов авторов и τ, недокачанные модели, ошибки и таймауты дочерних процессов, формулы бюджета, общий словарь, правки тренера авторов, параметры сэмплирования SGLang.
- После переписывания кода «для людей» (`runtime.py` → `common.py`, `training_data.py` → `training_common.py`, стадии в `orchestrate.py`) старая и новая версии на фейковом сервере выдали одни и те же 178 команд в том же порядке.
- После разбиения `profile_eagle.py` на шаги старая и новая версии на фейковой модели выдали одинаковые τ, число раундов, токенов и фаз.
- Хеши файлов кода не входят в настройки результата: правка комментариев не пересчитывает готовое. При изменении того, что измеряется, повышается `common.SCHEMA` (сейчас 4).
