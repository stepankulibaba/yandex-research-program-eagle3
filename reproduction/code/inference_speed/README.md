# EAGLE-3: ночной пакет после ревью

## Запуск на Linux / SLURM

Устанавливать окружения и скачивать модели лучше до восьмичасовой GPU allocation:

```bash
python3 orchestrate.py setup
bash check.sh
NIGHT_SECONDS=25200 bash night.sh
```

`check.sh` запускает GPU smoke; локально на Windows использовать только:

```powershell
py -3.12 -X utf8 layer_study/inference_speed/test_regressions.py
```

`NIGHT_SECONDS` — общий предел времени, по умолчанию семь часов, включая setup.
Если SLURM завершит процесс раньше, готовые стадии сохраняются. Следующий запуск
повторяет только стадии без подходящего проверенного `.done.json`.
`nohup`/отдельная process group не продлевают allocation.

Сохранять обе соседние директории `inference_speed` и `nemo_speed`.
Пути определяются от файлов, рабочая директория запуска может быть любой.
`run.sh` выполняет инференс/регенерацию; `../nemo_speed/run.sh` — обучение.
`ENV_ONLY=1` сохраняет совместимость с подготовкой окружений.
Режимы `main` и `smoke` полностью разделены.

## Приоритет стадий

1. Авторские EAGLE/baseline T=0 и T=1, по 80 вопросов.
2. Оригинальный и базовый NeMo тренеры в согласованном speed-only протоколе.
3. Проба регенерации и предварительный бюджет.
4. SGLang baseline и дерево статьи 8/10/60, затем 3/1/4, 5/8/32 и дерево EAGLE-2 6/10/60.
5. Варианты обучения: packing, FA2, compile, FP8, micro-batch 4.

Основной T=1 в SGLang имеет три seed. Это увеличивает объём работы:
завершение всего пакета за семь часов без серверных timings не гарантируется.
Общий дедлайн прекращает собственные процессы и сохраняет готовое.

## Где результаты

- `results/main/summary.md`, `summary.json`: авторские и SGLang результаты.
- `results/main/stages.json`: RUNNING / SUCCEEDED / REUSED / FAILED / UNSUPPORTED.
- `../nemo_speed/artifacts/main/summary.txt`, `summary.json`: обучение.
- `results/main/budget.md`, `budget.json`: предварительные сценарии стоимости.
- `logs/main/*.log`: отдельные логи стадий.
- Для smoke аналогичные файлы лежат в `smoke`.

Старые результаты прежнего протокола не удаляются и не принимаются автоматически.
Незавершённый benchmark архивируется перед повторным запуском.
Готовность требует совпадения версии протокола, manifest, хеша и полного покрытия.
Изменение исходников/окружения/данных инвалидирует соответствующие результаты.

## Протоколы

**3a:** официальный коммит `cb7e0841fe0c206c6ed74a197ad5e2a1f13f5a2b`,
авторские скрипты без изменений. Ускорение — отношение средних скоростей по вопросам.
Число verification rounds EAGLE — `idx + 1` на ход.

**3b:** SGLang `0.5.9`, serial HTTP requests, prefix cache выключен,
512 новых / 1979 общих токенов, явные EOS/eot, temperature/seed, очистка special tokens.
Сохраняются prompt IDs, текст, sampling parameters, finish reason и исходные metadata.
Output IDs сохраняются только если backend их возвращает; отсутствие не означает
подтверждённого совпадения токенов. Три T=1 seed показываются отдельно с разбросом.

HTTP latency и авторский CUDA generation timer имеют разные границы.
`completion/verify` и `verification tokens/round = accepted_draft/verify + 1`
публикуются раздельно; случаи нулевых rounds не удаляют весь benchmark.
Дерево авторов: 60 токенов, `--depth 7` (длина ветки 8), top-k 10 — глубина 8 из статьи EAGLE-3. В SGLang то же — 8/10/60; идентичность деревьев не утверждается.

**4:** адаптированный throughput-протокол, не неизменённое обучение статьи:
один авторский preprocessing на CPU, одинаковые input IDs/attention/loss masks
и 32K mapping; BF16; fixed padding 2048; eager target; TTT=7;
AdamW LR=5e-5 без decay; betas=.9/.95; clip=.5; micro=1/accum=2;
activation checkpointing выключен. В оригинале DeepSpeed управляет очисткой
градиентов на optimizer boundaries. Порядок данных фиксирован, workers=0.

Warm-up задаётся в optimizer steps: `WARMUP=20`. Smoke использует warm-up=0,
чтобы даже короткий packed/mb4 запуск проверял полный цикл. Его времена не
используются как оценка steady-state скорости или GPU-бюджета основного прогона.
Токены/документы реально считаются в окне; таймер синхронизирует CUDA на границах.
Отчёт содержит ms/optimizer-step, nonpad/padded/supervised tokens/s и обе
метрики peak памяти PyTorch. Evaluation, preprocessing и запись checkpoint
в throughput не входят. Разные реализации TTT не означают доказанного
численного/градиентного паритета или совпадения качества после обучения.

Packing изменяет состав строк. mb4 увеличивает effective batch с 2 до 4 строк —
его шаг нельзя называть той же работой. FA2 относится к draft attention.
При отсутствии FA2 вариант пропускается с UNSUPPORTED, eager под этим именем нет.
Compile и FP8 проверяются по реально изменённым модулям.

**5:** multi-turn проба ShareGPT/UltraChat, три группы длин, та же SYS/1900-token
policy. Сэмплы и успешные регенерации сохраняются для восстановления.
Вес групп оценивается по ограниченному скану, это пилот, не полный census.
Размеры 68K/464K — предположения из задания; реальные retained размеры неизвестны.
Бюджет включает операционный резерв (по умолчанию 10h) и диапазон чувствительности,
который не является доверительным интервалом и не доказывает достаточность 100h.
`--already-regenerated` переключает формулу доли на фиксированную стоимость
уже перегенерированного полного корпуса. Размер кеша относится только к hidden states.

## Среда и безопасность процессов

Модели и исходники закреплены SHA в `runtime.py`; датасеты — revision в коде.
Проверяются все файлы HF manifest, размеры, индексы и safetensors headers.
Tokenizer mirror patch находится в загрузчике и применяется в обоих режимах.

SGLang использует Triton attention / PyTorch sampling; DeepGEMM JIT выключен.
Это не гарантирует доступность всех kernels: GPU smoke обязателен.
Проверка tree sampling kernel блокирует тихий greedy fallback при T=1.
Для compile/kernels требуются gcc/g++/ninja. CUDA версии для DeepSpeed берутся
из PyTorch, заглушка nvcc ограничена установкой. FA2 extra без toolkit
не устанавливается автоматически; `TRY_FA2=1` явно разрешает попытку.

Процессы запускаются в принадлежащих оркестратору группах. Завершение включает
workers, имеет ограниченное ожидание и работает при SIGTERM/ошибке/дедлайне.
Занятый порт приводит к ошибке; чужой процесс не завершается.
Workspace lock не разрешает два одновременных запуска этого пакета.
